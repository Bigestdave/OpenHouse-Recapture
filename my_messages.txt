import * as React from "react";
import { cva, type VariantProps } from "class-variance-authority";

function cn(...inputs: (string | undefined | null | false)[]): string {
  return inputs.filter(Boolean).join(" ");
}

const glassButtonVariants = cva(
  "relative isolate all-unset cursor-pointer rounded-full transition-all",
  {
    variants: {
      size: {
        default: "text-base font-medium",
        sm: "text-sm font-medium",
        lg: "text-lg font-medium",
        icon: "h-10 w-10",
      },
    },
    defaultVariants: {
      size: "default",
    },
  }
);

const glassButtonTextVariants = cva(
  "glass-button-text relative block select-none tracking-tighter",
  {
    variants: {
      size: {
        default: "px-6 py-3.5",
        sm: "px-4 py-2",
        lg: "px-8 py-4",
        icon: "flex h-10 w-10 items-center justify-center",
      },
    },
    defaultVariants: {
      size: "default",
    },
  }
);

export interface GlassButtonProps
  extends React.ButtonHTMLAttributes<HTMLButtonElement>,
    VariantProps<typeof glassButtonVariants> {
  contentClassName?: string;
}

const GlassButton = React.forwardRef<HTMLButtonElement, GlassButtonProps>(
  ({ className, children, size, contentClassName, ...props }, ref) => {
    return (
      <div
        className={cn(
          "glass-button-wrap cursor-pointer rounded-full",
          className
        )}
      >
        <button
          className={cn("glass-button", glassButtonVariants({ size }))}
          ref={ref}
          {...props}
        >
          <span
            className={cn(
              glassButtonTextVariants({ size }),
              contentClassName
            )}
          >
            {children}
          </span>
        </button>
        <div className="glass-button-shadow rounded-full"></div>
      </div>
    );
  }
);
GlassButton.displayName = "GlassButton";

export { GlassButton, glassButtonVariants };

One-sentence pitch
OpenHouse detects when a property is listed, evaluates whether its phone capture is sufficient, requests missing footage, orchestrates 3D reconstruction, verifies the result, and publishes an interactive mobile walkthrough—without requiring the realtor to become a 3D technician.

1. The problem
Property listings are still largely collections of disconnected photographs.
Those photographs may show how individual rooms look, but they often fail to communicate:
How rooms connect
The scale and flow of the property
What exists outside the camera’s chosen angles
Whether the property is worth an in-person visit
Which room satisfies a renter’s priorities
Interactive property tours can solve part of this problem, but producing one remains a specialist workflow. Someone must:
Capture the property correctly.
Determine whether the footage has sufficient coverage.
Process and align hundreds of frames.
Generate the spatial representation.
Clean reconstruction artefacts.
Optimise the output for mobile devices.
Create navigation and annotations.
Host and attach the experience to the listing.
The underlying 3D technology exists. The unresolved problem is making that fragmented process reliable and usable for ordinary property teams.
The bottleneck is no longer whether an immersive tour can exist. It is everything required to turn messy property media into a trustworthy, publishable experience.

2. The solution
OpenHouse acts as the production manager between a newly published property and its interactive experience.
A realtor performs one guided phone walkthrough and publishes the listing normally.
OpenHouse then:
Detects the new listing.
Collects its video, photographs, description, and floor plan.
Understands what rooms and features should exist.
Checks capture quality and completeness.
Identifies missing, blurred, or contradictory evidence.
Requests only the specific footage needed.
Runs the approved 3D reconstruction pipeline.
Inspects the generated result for obvious inconsistencies.
Optimises it for mobile delivery.
Adds room labels and guided navigation.
Publishes an “Explore this home” experience.
Answers grounded questions about the property.
The realtor does not need to understand COLMAP, Gaussian splatting, camera poses, GPU training, compression, WebGL, or hosting.

3. The defining insight
We are not inventing Gaussian splatting
Gaussian splatting is one tool inside the system.
The innovation is an agent that can manage the uncertain, multi-stage workflow around it.
Most 3D pipelines assume that the operator knows:
How to capture a suitable video
Whether there is enough overlap
Why reconstruction failed
Which parts need to be recaptured
How to clean the result
How far it can be compressed
Whether it is safe to publish
OpenHouse makes those decisions.
The reconstruction engine creates the scene. OpenHouse decides whether the scene deserves to be published.
That is the heart of the project.

Independent realtors, property managers, short-let operators, and small real-estate agencies that cannot send a professional spatial-capture team to every property.

Renters and remote buyers who want to understand a property before scheduling an inspection.
Particularly relevant users
Renters comparing many properties
Diaspora buyers unable to inspect personally
Short-let guests
Property managers handling multiple units

6. What makes it genuinely agentic
A webhook followed by a fixed reconstruction script is automation—not sufficient agency.
OpenHouse demonstrates agency by making bounded decisions under uncertainty.
The agent must determine:
Whether the listing contains enough evidence
Which images belong to which rooms
Whether all advertised rooms were captured
Whether a blurred section should be discarded or recaptured
Whether the camera trajectory contains enough overlap
Which reconstruction configuration is appropriate
Whether a generated view contradicts the source footage
Whether to retry, request evidence, escalate, or continue
Whether the result meets the publication threshold
It also waits for external events and resumes later.
The most important demonstration of agency is not the successful reconstruction. It is this:
The system recognises that it cannot complete the job safely, explains exactly what is missing, obtains the missing evidence, and continues from where it stopped.

11. Measurement policy
A Gaussian splat should not be presented as survey-grade geometry.

Verified
Derived from:

Confirmed reference measurement
Estimated
Derived from incomplete or lower-confidence evidence and clearly labelled as approximate.
Unavailable
The agent explains that no reliable scale evidence exists.

This refusal makes the product more credible—not less impressive.

17. Devpost-ready description
Inspiration
Property photographs show rooms, but they rarely show how a home feels as a connected space. Interactive tours can solve this, yet producing them still requires careful capture, specialised reconstruction software, manual cleanup, optimisation, and publishing.
We asked:
What if a realtor could publish a property normally and an agent handled everything required to turn it into an immersive experience?
What it does
OpenHouse detects new property listings and converts suitable phone captures into interactive mobile walkthroughs.
Before reconstructing anything, it uses Gemini to understand the listing and evaluate whether the available media adequately covers the advertised property. If evidence is missing or defective, it pauses the workflow and requests a specific recapture.
Once the evidence is sufficient, OpenHouse orchestrates the reconstruction pipeline, generates verification views, compares the result against its source material, and publishes only after the experience passes defined quality checks.
The result is attached to the listing as an “Explore this home” link that renters can open directly in a browser.
What makes it different
OpenHouse is not another 3D generator.
It is an autonomous production and quality-control system for property experiences. Its primary value is not the underlying rendering method, but its ability to manage uncertain inputs, recover from capture failures, coordinate specialised tools, preserve workflow state, and prevent unsupported results from being published.
How we built it
OpenHouse uses Google ADK and Gemini for orchestration, multimodal evidence assessment, capture guidance, and visual verification. Google Cloud manages event delivery, state, media storage, asynchronous jobs, logging, and deployment.
The spatial pipeline uses established computer-vision and Gaussian-splatting tools. The final experience is optimised and delivered through an embeddable browser viewer.
Challenges
The largest challenge was distinguishing photorealistic appearance from reliable spatial evidence. A convincing reconstruction is not automatically dimensionally accurate.
We addressed this through:
Explicit evidence states
Source-to-render verification
Confidence-gated publication
Human approval
Strict measurement policies
What’s next
Future versions could support:
Property-platform integrations
LiDAR-assisted capture
Floor-plan reconciliation
Verified furniture placement
Personalised guided tours
Accessibility assessments
Renovation and furnishing simulations
Portfolio-scale processing for property managers

OpenHouse detects when a property is listed, evaluates whether its phone capture is sufficient, requests missing footage, orchestrates 3D reconstruction, verifies the result, and publishes an interactive mobile walkthrough—without requiring the realtor to become a 3D technician.

1. The problem
Property listings are still largely collections of disconnected photographs.
Those photographs may show how individual rooms look, but they often fail to communicate:
How rooms connect
The scale and flow of the property
What exists outside the camera’s chosen angles
Whether the property is worth an in-person visit
Which room satisfies a renter’s priorities
Interactive property tours can solve part of this problem, but producing one remains a specialist workflow. Someone must:
Capture the property correctly.
Determine whether the footage has sufficient coverage.
Process and align hundreds of frames.
Generate the spatial representation.
Clean reconstruction artefacts.
Optimise the output for mobile devices.
Create navigation and annotations.
Host and attach the experience to the listing.
The underlying 3D technology exists. The unresolved problem is making that fragmented process reliable and usable for ordinary property teams.
The bottleneck is no longer whether an immersive tour can exist. It is everything required to turn messy property media into a trustworthy, publishable experience.

2. The solution
OpenHouse acts as the production manager between a newly published property and its interactive experience.
A realtor performs one guided phone walkthrough and publishes the listing normally.
OpenHouse then:
Detects the new listing.
Collects its video, photographs, description, and floor plan.
Understands what rooms and features should exist.
Checks capture quality and completeness.
Identifies missing, blurred, or contradictory evidence.
Requests only the specific footage needed.
Runs the approved 3D reconstruction pipeline.
Inspects the generated result for obvious inconsistencies.
Optimises it for mobile delivery.
Adds room labels and guided navigation.
Publishes an “Explore this home” experience.
Answers grounded questions about the property.
The realtor does not need to understand COLMAP, Gaussian splatting, camera poses, GPU training, compression, WebGL, or hosting.

3. The defining insight
We are not inventing Gaussian splatting
Gaussian splatting is one tool inside the system.
The innovation is an agent that can manage the uncertain, multi-stage workflow around it.
Most 3D pipelines assume that the operator knows:
How to capture a suitable video
Whether there is enough overlap
Why reconstruction failed
Which parts need to be recaptured
How to clean the result
How far it can be compressed
Whether it is safe to publish
OpenHouse makes those decisions.
The reconstruction engine creates the scene. OpenHouse decides whether the scene deserves to be published.
That is the heart of the project.

6. What makes it genuinely agentic
A webhook followed by a fixed reconstruction script is automation—not sufficient agency.
OpenHouse demonstrates agency by making bounded decisions under uncertainty.
The agent must determine:
Whether the listing contains enough evidence
Which images belong to which rooms
Whether all advertised rooms were captured
Whether a blurred section should be discarded or recaptured
Whether the camera trajectory contains enough overlap
Which reconstruction configuration is appropriate
Whether a generated view contradicts the source footage
Whether to retry, request evidence, escalate, or continue
Whether the result meets the publication threshold
It also waits for external events and resumes later.
The most important demonstration of agency is not the successful reconstruction. It is this:
The system recognises that it cannot complete the job safely, explains exactly what is missing, obtains the missing evidence, and continues from where it stopped.

Estimated

Unavailable

17. Devpost-ready description
Inspiration
Property photographs show rooms, but they rarely show how a home feels as a connected space. Interactive tours can solve this, yet producing them still requires careful capture, specialised reconstruction software, manual cleanup, optimisation, and publishing.
We asked:
What if a realtor could publish a property normally and an agent handled everything required to turn it into an immersive experience?
What it does
OpenHouse detects new property listings and converts suitable phone captures into interactive mobile walkthroughs.
Before reconstructing anything, it uses Gemini to understand the listing and evaluate whether the available media adequately covers the advertised property. If evidence is missing or defective, it pauses the workflow and requests a specific recapture.
Once the evidence is sufficient, OpenHouse orchestrates the reconstruction pipeline, generates verification views, compares the result against its source material, and publishes only after the experience passes defined quality checks.
The result is attached to the listing as an “Explore this home” link that renters can open directly in a browser.
What makes it different
OpenHouse is not another 3D generator.
It is an autonomous production and quality-control system for property experiences. Its primary value is not the underlying rendering method, but its ability to manage uncertain inputs, recover from capture failures, coordinate specialised tools, preserve workflow state, and prevent unsupported results from being published.
How we built it
OpenHouse uses Google ADK and Gemini for orchestration, multimodal evidence assessment, capture guidance, and visual verification. Google Cloud manages event delivery, state, media storage, asynchronous jobs, logging, and deployment.
The spatial pipeline uses established computer-vision and Gaussian-splatting tools. The final experience is optimised and delivered through an embeddable browser viewer.
Challenges
The largest challenge was distinguishing photorealistic appearance from reliable spatial evidence. A convincing reconstruction is not automatically dimensionally accurate.
We addressed this through:
Explicit evidence states
Source-to-render verification
Confidence-gated publication
Human approval
Strict measurement policies
What’s next
Future versions could support:
Property-platform integrations
LiDAR-assisted capture
Floor-plan reconciliation
Verified furniture placement
Personalised guided tours
Accessibility assessments
Renovation and furnishing simulations
Portfolio-scale processing for property managers
